    The Control Unit

    Our datapath is built — but right now it is a tangle of idle wires with no idea what to do. The piece that brings it to life is the control unit, the brain that reads each instruction’s opcode and, from that alone, throws every switch the datapath needs: whether a register is written, which operand the ALU takes, whether memory is read or written, and where the program counter goes next. In this lesson we watch that decoding happen, one case at a time.

    Decoding by Opcode

    At its heart, the control unit is one big lookup: it takes the instruction’s opcode (and, when it needs to tell two similar instructions apart, the funct3 field) and produces the exact set of control signals that steers this instruction through the datapath. A single case statement captures the whole idea — each opcode lights up its own handful of switches and leaves the rest at their default of 0.
